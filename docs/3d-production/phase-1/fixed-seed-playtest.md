# 固定种子对照试玩

2026-09-22。入口用于 Phase 1 同种子、同起点的真人对照，不代表真人验收已完成。

## macOS 操作

1. 双击 `Godot/three_d/固定种子试玩.command`。
2. 输入约定的正整数编号（1–2147483646）；直接回车使用 20260922。
3. 进入藏匿点后确认顶部出现“对照试玩 · 编号 … · 本次不读写正式存档”。
4. 按协议选择同一家酒馆并确认出发，此时开始整局计时。新启动的金库为 1200，出发携带 300。
5. 一位测试者完成后关闭窗口。下一位必须重新双击启动，输入同一编号；不要直接在上一位的窗口开第二局，因为该窗口的金库已有变化。

此入口不加载、写入或覆盖正式存档；关闭后本次试玩进度不保留，但独立取证轨迹会留下。需要检验读档流程时使用专门的存档测试，不用本模式证明读档体验。正常的“启动3D原型.command”继续使用原有进度与随机出发。

## 2026-09-29 首轮真人观察重点

建议先用提交 `7b3968d`、编号 `20260922`、烟雾酒馆做一次自然玩法测试；若有第一次玩本作的参与者，让其在另一个新窗口用相同版本、编号和起点独立游玩。只告诉参与者 WASD 移动、鼠标观察、E 交互、B 背包，不提前讲解下注或撤离策略。首轮不要求完成四桌，也不把未完成四桌记为操作失败。

现场记录三件事：①确认出发、首桌开打、撤离或失败的时刻；②玩家在买不起下一桌时看到的现金与买入额、是否主动想到按 B 查看已知路线、是否找到可用出口以及选择理由；③玩家对出口手续费、丢弃现金与预计到账能否作出正确复述。若卡住或按错，不替玩家完成操作，记录其原话与画面。测试结束后保留 `PLAYTEST_TRACE` 原始 JSONL；轨迹没有记录理解程度、未打开的交互点和口述理由，所以仍需现场笔记。

自动诊断在 12 个固定种子、固定保守玩家策略下得到 1 条四桌普通撤离、11 条买入不足后紧急撤离；这不是预计真人通关率。真人观察应判断现金门槛及退路是否清楚，不应让参与者模仿自动策略来复现该比例。

## 其他平台或命令行

```sh
/path/to/Godot --path Godot --scene res://three_d/scenes/main.tscn -- --playtest-seed=20260922
```

真人试玩不要加 `--test`；那是自动化开关，会改变鼠标捕获、失焦暂停等行为。固定种子参数本身已隔离存档，仍保留正常的鼠标、暂停和关闭行为。缺值、重复参数、非整数或越界编号会终止启动，不回退成随机局。

## 对照边界与记录

同编号、同代码版本、同酒馆、同初始资金才能比较。种子控制初始货架、接应、对手、事件和桌面种子；不同行动可使后续游戏状态与 RNG 消耗分叉，不能保证两位玩家永远收到相同的后续局面。

本入口不强制路线或代替玩家作选择。轨迹现会记录固定种子模式中打开的出发/转场/撤离面板、背包与服务面板、入座选择，以及轮到玩家时的扑克合法动作集；成功动作关联到对应的 `opportunity_id`，服务和牌桌输入被规则拒绝时单独记为 `decision_attempt_rejected`。自动推进事件仍单独标记，不能计为玩家决策。记录者仍需按协议填写测试者组别、理由、复盘、代码提交、编号、酒馆/桌序/撤离路线和实际时刻；不要将自动测试日志当真人数据。

固定种子模式在**首次记录机会或操作后**，会向终端打印 `PLAYTEST_TRACE` 后的绝对路径，并在 `user://playtest-traces/` 写一份独立 JSONL 文件。macOS 默认目录可在 Finder 的“前往文件夹”输入 `~/Library/Application Support/Godot/app_userdata/Godot德扑酒馆/playtest-traces/`。每行有时间、种子、操作类别、选择及操作后的资金/风声；机会行另含合法选项、前置资金/风声/行动力/牌局快照。成功选择会关联机会 ID；被拒绝的服务/扑克输入作为单独尝试记录。`next_hand`、`table_settled` 等自动/必经步骤不应计入有效决策。世界行走与未打开的交互点不会作为决策机会写入，因此此轨迹不是整个游戏的完整机会分母，也不能单独代替真人记录理由。

可用 Python 汇总器分开核对机会、输入尝试和有效决策：

```sh
python3 Godot/three_d/tests/analyze_playtest_trace.py /path/to/seed-trace.jsonl --output /path/to/summary.json
```

汇总器只把存在关联机会、选择与当时提供选项匹配、成功改变状态且至少有两个合法选项的动作计入有效决策。没有机会记录的旧轨迹会列为不可分类；“某次机会没有记录动作”只表示轨迹未看到已接受动作，不证明测试者确实看过或理解该面板。分析报告中的覆盖说明必须与结果一起保留。

## 正式记录怎么分开做

**新老手对照**：至少一位没玩过本作的新手和一位已玩过本作的老手，分别在新窗口使用同一代码版本、同一正整数种子、同一家酒馆，约定同一桌序与撤离路径。不要强迫两人选择相同下注或道具；从第一处不同决定起，后续牌局与 RNG 可能分叉，不能再把第 N 条记录当作同一局面。逐次记下至少两个合法玩法选项中**成功执行、改变状态**的选择；被拒绝、只看面板和走位不计。每条至少记录玩家组别、机会 ID、实际选择、前置资金/风声/牌局状态、执行结果、分叉标记与复盘理由。主指标是两人有效决策事件总数的**绝对差 >3**，同时保留原始事件；差值通过仍需核对两人的路径与理由，不能把局时差异或没看懂规则误判为策略深度。若某人无法走完约定桌序或路线，如实记录偏离，不能把它改写成“同路径”通过。

**正常局计时**：另开全新窗口，按自然决策推进本店后续牌桌或跨酒馆，直到完成撤离或失败；不要拿只打第一桌的 [16 步安全路线](first-run-walkthrough.md) 判断 20–30 分钟目标。`T_start` 是确认带钱出发，`T_extract` 是付款完成、回到藏匿点；首桌开打另记。若提前失败，另记失败时刻与原因，和完成撤离的局分开报告，不把失败时刻伪作 `T_extract`。阅读、探索、购买和思考的实际时间都计入，异常离席单独注明，不用等待动画凑时长。记录代码版本、种子、玩家组别、酒馆与桌序、三个时刻、撤离结果及偏离原因。这两类试玩都还没有可验收的真人实测数据。

## 验证

`playtest_seed_test.gd` 检查参数校验、正常模式保留、固定种子出发、统一资金、方案复现、机会选项/ID 与接受和拒绝动作的关联，以及直接调用保存函数也不写正式存档。`test_playtest_trace_analysis.py` 用合成轨迹核验机会、尝试、有效决策分计数、缺失关联和无效选项处理。测试仅使用专用临时路径；完整真人体验与计时仍待执行。
