# Phase 1：状态机与守恒验收草案

2026-09-13。当前实现的核验规格，不是“已形式证明”。证据覆盖不足的维度必须保持未通过。

## 权威状态

Run 管理资金、库存、抵押、风声、行动力、已完成牌桌、酒馆和搜索结果；Table 管理牌堆、底牌、公共牌、筹码、行动队列、种子 RNG。World 管理实际位置/房间、视线、入座、暂停和交互动画。RunCheckpoint 与 TableCheckpoint 保存状态，SaveStore 写入文件。

| 状态 | 允许的转移 | 拒绝的转移/门槛 |
|---|---|---|
| 藏匿点，无活动局 | 选择酒馆并扣带出资金；破产时显式重置试玩资金 | 活动局不能再扣一次出发金额；金库 <120 不能正常出发 |
| 探索，未入座 | 看物件、购买/出售、搜索事件、查情报、降风声、路线预约/发现/撤离 | 动作点不足；不拥有道具；重复搜索；未解锁房间；距离/遮挡不符 |
| 入座，未买入 | 选择抵押、开桌扣买入、取消回探索 | 抵押非贵重物/非自有物；现金不足；已打过的桌 |
| 牌局进行 | 玩家合法行动、轮到 AI 时行动、无人待行动时推进街道；限定道具 | 非当前玩家行动；旧 revision；非法下注；探索服务或中途结算 |
| 单手结束，未终桌 | 下一手；暂停/恢复 | 重复支付底池；再次下注 |
| 终桌，待离座 | 返还筹码、处理抵押和奖励、刷新行动力、标记完成 | 结算只可一次；先结算余烬降风声再判断封锁 |
| 探索且风声 6 | 选择可用最优紧急路线；无出口失败结算 | 不得让旧弹窗覆盖新状态；不能无视失效预约 |
| 撤离/放弃后回藏匿点 | 本局清空随身财物，更新金库；下一局 | 不能二次到账；新局不继承路线或搜索领奖标记 |
| 暂停/保存/恢复 | 保存有权威状态的副本；恢复后暂停等待玩家 | 无效存档保留原文件；禁止用错误房间恢复另一张桌 |

以上是转移类别目录，**尚未拆成全部守卫分支与唯一转移 ID**。因此尚无 ≥95% 覆盖率结论。

## 守恒等式与验证边界

- 出发：`金库减少 = 带出本金 = 随身现金增加`。金库在本局内不能随意提款。
- 入桌：`随身现金减少 = 玩家初始筹码`；抵押只是从背包移入托管，不是奖励销毁。筹码只在合法行动/盲注/底池结算转移。
- 单手：`所有玩家剩余筹码 + 未分配底池 = 本手开始总筹码`。全押、边池、零筹码、平分余数均需独立用例；既有 poker/table 测试是证据，不能代替所有世界状态的验证。
- 离桌：随身增加恰等于玩家剩余筹码；抵押主池胜出或并列时归还，否则登记损失；奖励属于显式来源，不能算成无来源增值。
- 商店/搜索：每一笔现金或物品变化对应价格、奖励、消耗或事件选择；失败请求的全量状态不变。物品“数量守恒”需包含奖励来源、使用/出售/丢弃去向。
- 成功撤离：`原现金 + 原贵重物价值 = 到账 + 手续费 + 舍弃现金 + 舍弃贵重物价值`。金库增加恰为到账，随身库存清空，重复确认拒绝。
- 失败：金库增加仅来自夹层钱包实际保留金额；其余现金和物品登记为损失，不把“失败”与“某出口被拒绝”混为一谈。
- 风声不是守恒资源，是受限状态：范围 0..6，每个增减有唯一动作来源，封锁在规定阶段处理。
- 位置不是金额守恒：合法出生、墙体碰撞、2 米射线、区域/牌桌一致性均须满足。玩家真实连续行走测试与仅设置坐标测试要分开记证据。
- RNG：同一状态与同一动作序列必须产生同一后继状态；读档不得多消耗随机数。种子已覆盖房间连接、货架、事件、对手与发牌计划，跨酒馆保留整晚机会；具体证据见 seeded-pools.md 与 cross-venue-evening.md，仍不能宣称全部动作序列已验证。

## 本轮已复现并修复

BUG-P1-001：现金 10–15 时“丢现金撤离”原来可出现手续费加损失超过本金。例如现金 10 时显示费用 10、损失 4，却仍返回零现金。修复为舍弃额 `min(floor(现金×40%), max(0,现金−费用))`：仍保留最低 10 现金可紧急撤离的既有规则，实际舍弃不超过缴费后的余额。正常较高余额规则不变。网页历史版本未修改。

`extraction_conservation_test.gd` 修复前出现余额差额，修复后对现金 0..200、风声 0..6、四酒馆、六出口共 33,768 个报价组合测试，25,481 个可用报价的等式差额全部为 0，实际到账与报价一致，重复到账拒绝。该原矩阵固定每酒馆第一预约方案、路线已知、背包一枚象牙筹码。2026-09-23 又增加 9,072 个边界状态：四酒馆、两个预约方案、零/一/三件贵重物、无预约/有效/过期、六出口、七档现金与三档风声；2,796 个可用报价的守恒式、实际金库入账、库存清空和拒绝后的完整快照均通过。新增矩阵的现金、背包和预约是状态夹具，不能当成从真实搜索/购买/牌局逐步走出的完整局；因此仍不等于全状态机证明。

## 2026-09-22：首次进攻优惠的显示与验收口径

保持当前货运桌规则：每手全桌首次 raise 少实付 10，玩家和对手均可使用；目标下注额不减，底池只记录实际进入的筹码，派彩仍按实际贡献分层。它不是庄家向底池补贴 10。不能用“目标下注额 × 人数”代替实际投入计算底池守恒。同手后续进攻不再优惠，下一手重置；直接 all-in 按实际剩余筹码投入。

牌桌增加实时成本提示，随加注数值变化显示目标额、实付和优惠；实际会转换为全押时明确提示全押成本和实际下注额。`raise_preview_test.gd` 四桌共 33 项检查通过，最小、自选、最大金额的提示与 Table.act 实际扣款一致；two_tables 27 项通过。渲染检查见 `output/3d/raise-preview.png`，为独立牌桌 HUD 测试图，不是完整美术场景。

A2 关于“刚好跟注打光是否出局”的疑问：本手 stack=0 且未弃牌仍有摊牌资格；只有本手结算后依然为零才不参与下一手。不能在跟注刚完成时就推断下一手出局。优惠在边池中的实际策略价值仍需真人体验评估，此次未改动下注或派彩算法。
