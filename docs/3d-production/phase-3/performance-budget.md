# Phase 3 性能基线与待定预算

2026-09-29。目标仍是目标中端 Mac、Windows 上的游戏实测 ≥60 fps，以及连续游玩 ≥30 分钟无明显掉帧或内存增长。60 fps 对应每帧约 16.67 ms；这不是单个模型、GPU 或脚本可独占的预算。目标机型和画质档未确定，因此暂不分配逐资产面数/贴图/灯光上限，也不判定 Phase 3 性能通过。

## 可复测的本机起点

- 命令：`/Applications/Godot.app/Contents/MacOS/Godot --path Godot --script res://three_d/tools/perf_baseline.gd -- --test`。脚本以有窗口的 Metal / Forward Plus 启动游戏，先在藏匿点静止视角采样，再通过正常的出发动作到烟雾酒馆货运桌视角采样；每处预热 120 帧、记录 300 个渲染回调间隔。`--test` 关闭正式存档读取/写入和鼠标锁定。
- 环境：MacBook Pro Mac17,2，Apple M5，24 GB；Godot 4.7.2；游戏窗口/视口 1376×768；垂直同步模式 1。三次连续独立启动均退出码 0，场景切换成功。

| 场景 | 三次中位回调间隔（ms） | 三次 p95 回调间隔（ms） | FPS 监视值 | 渲染内存监视值 |
|---|---|---|---|---|
| 藏匿点 | 8.279–8.295 | 9.144–9.220 | 120 | 474,234,880 B |
| 烟雾酒馆货运桌视角 | 8.205–8.224 | 9.043–9.205 | 120–121 | 482,115,584 B |

这里测的是**静止视角的 Godot 渲染回调间隔**，可能受到 120 Hz 显示节奏、窗口调度和缓存影响；FPS 监视值也不是独立的 GPU 计时。内存字段仅为 Godot 报告的渲染内存，不代表进程总内存。此样本不能推出移动、灯光变化、四店切换、最重牌室、Windows 或 30 分钟稳定性。脚本每次覆盖 `output/3d/perf-baseline.json`；该文件是本地原始记录，范围以本页及脚本为准。

## W0 余下测量

高级模型选定目标 Mac/Windows 中端机型、显示分辨率和低/中/高画质档后，先用同一走位/镜头路径记录原版，再对每批高模资产重复。至少包含藏匿点近景、吧台货架、牌桌入座、后厨楼梯、河边坡道、四店切换；另以真实游玩持续 30 分钟记录 FPS 分位数、CPU/GPU 帧时和进程/渲染内存曲线。性能超预算时优化运行网格、材质、灯光和 LOD，再比较画质与可读性；不能用本页静态样本给最终资产放行。


## 2026-10-03：生产对手 CPU 决策耗时

新增 ai_perf_probe.gd，从四桌正式定义、seed 301 开始，用生产 Opponent.choose 与 table.rng.next 推进对手行动，玩家采用合法 check/call/fold，四桌均自然终结；没有改对手策略、蒙特卡洛试验数或随机种子。测量包含 equity 估计，不包含 Godot 画面刷新/GPU。原始记录为 output/3d/ai-perf-probe-before.json、ai-perf-probe.json；对账为 ai-perf-comparison.json。

发现 evaluate_best_hand 对最多 21 个五张组合都深复制、排序最终展示牌；目前先计算组合分数，只在选定原先同一最佳组合后构建完整展示结果。对手数、试验数、权重、RNG 消耗及比较逻辑不变。

本机 Apple M5 / Godot 4.7.2 headless CPU 同口径单次前后样本均为 20 次决策：中位耗时 23.299 → 16.073 ms，p95 32.712 → 18.657 ms，最大 34.936 → 19.223 ms。中位下降约 31.0%。逐项比对演员、桌、街道、手数和动作以及各桌步数/终结状态，均相同。单次样本不能证明稳定收益或达到 60 fps；优化后较慢决策仍超过 16.67 ms 的整帧预算，渲染及其他脚本还需要时间，主线程卡顿与目标设备测试继续待处理。

hand_evaluation_equivalence_test.gd 以原有逐组合完整五张结果选择方式作为参考，覆盖现有牌型 fixture、100 个种子的 4/5/6/7 张样本和同分不同花色候选；1414 个输入、4242 项断言通过。比较完整 rank/values/name/cards，输入不得变化，返回牌面不得引用输入字典。该专项证明优化后的选择与展示复制保持，不把它当成所有德扑规则的穷举证明。现有独立牌型/RNG fixture 1424 项及浏览器牌桌 parity 111 样本亦通过。

最终完整回归：output/3d/regression/20261003-201735/report.json，71/71 个 Godot 套件与 20/20 个 Python 测试通过，运行期间源码、测试与资产指纹未变。此结论仍不是目标平台 60 fps 验收。


## 2026-10-03：AI 七张牌直接评分

原有完整牌型/展示接口继续按五张组合选择并生成独立展示副本；AI equity 只需要 rank 与 tiebreak values，新增 score_seven 直接统计七张牌的点数/花色，处理同花顺、四条、两个三条形成葫芦、同花、轮子顺子、三条、三对中的最佳两对、一对和高牌。straight_high 只读扫描降序点数。estimate_odds 仍进行 85 次原有洗牌和比较，种子、试验次序、牌堆复制、对手私牌抽取和随机数消耗不变；已完整的河牌可复用玩家评分。没有改变策略参数或下注规则。

seven_card_score_test.gd 用原逐组合 evaluate_best_hand 为独立参考，对现有七张牌 fixture 与 10000 个固定种子手牌逐项比对 rank/values 和输入不变，20691 项检查通过，包含九类完整牌型。equity_equivalence_test.gd 保留优化前 equity 流程，用公开完整牌型接口和原洗牌验证四街道、1/2 对手、四种种子及公共皇家同花顺平分：34 组、66 项检查全部通过，胜率以精确 float 相等比较，而非容差。

本机三次完整四桌 CPU 探针各 20 次对手决策：中位 4.509–4.692 ms，p95 5.278–6.336 ms，最大 6.123–6.823 ms；演员/桌/街道/手数/动作序列与第一轮优化记录全部一致，各桌终结路径相同。原始报告 ai-perf-seven-card-1/2/3.json，对账 ai-perf-seven-card-comparison.json。本次范围为 Apple M5 上的 CPU-only 决策，不包含画面重建、GPU 或目标中端机器；不能以这些值替代 60 fps 与 30 分钟验收。

本轮完整回归 output/3d/regression/20261003-203614/report.json：73/73 个 Godot 套件、20/20 个 Python 测试通过，运行期间源码、测试及运行资产指纹未变。源码审计归属新增两个纯计算 helper，没有新增状态转移 ID；整体分母仍未冻结。
