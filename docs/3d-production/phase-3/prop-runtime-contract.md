## 从当前 Godot 资产重导

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path Godot --script res://three_d/tools/export_prop_contract.gd
```

输出 `output/3d/prop-contract.json`，每次覆盖：全部规则 ID、是否有模型、Godot 本地包围盒（米）、原点、根缩放、三角面及材质表面数，并记录规则文件和 GLB 的 SHA256。脚本只实例化视觉包，不创建游戏世界，不访问玩家存档。

## Blender 精修与游戏接入步骤

1. 先校准尺寸和原点，再精修材质/细节。Godot 的单位为米、Y 向上；当前源脚本的 Blender 转换是 `(x, -z, y)`。导出到现有视觉包时保留规则 ID 和根层级，物件内部网格可以调整。
2. 保留 drawer / loose-card / loose-chip 三个已有交互件及其独立原点，避免替换视觉包时损失抽屉、翻牌和筹码旋转表现。
3. 每次改变九件商店物品的尺寸，都要复核 `bar_display.gd` 的货架底部偏移和射线范围。目前底部偏移是逐 ID 的固定值，不能只更新 GLB 就声称货架接入通过。
4. 递物由酒保 `hand.R` 骨附着，打火机有专用方向，其余商品沿用默认方向。新尺寸要同时检查掌面高度、手指接触、袖口穿插和递物结束的缩小/移除过程。不要借此修改购买、背包或消耗规则。
5. 十件贵重物加入视觉包后，重导本页 JSON，应为 19/19 有模型；还须接入其实际可见用途并逐件核验奖励/持有/抵押/出售表现。仅把十个隐藏网格放进文件不等于实体化验收。
6. 在正常玩家视角下检查近景与空间可读性，记录真实截图；按当前美术规格做磨损、玻璃和金属细节，再测量性能。静态包围盒、面数与文件大小不代替视觉或性能验收。

本轮只增加运行几何导出与接入说明，未改美术资产、交易显示代码或玩法。角色精修仍由另一模型维护；本页尺寸可供其后续物品制作直接核对。
