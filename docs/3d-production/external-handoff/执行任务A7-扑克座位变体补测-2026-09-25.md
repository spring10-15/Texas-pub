# 执行任务 A7：扑克队列座位变体补测

## 目标

补齐 `docs/3d-production/phase-1/coverage/transitions.json` 当前仍待审的两类扑克队列边界：

- `short_all_in_raise_seat_variants`
- `lone_funded_queue_heads_up_variants`

主 Agent 已在 `short_stack_queue_test.gd` 验证四桌规则 × 三个行动座位 × 短额/精确跟注全押共 24 个前置组合，并将前两类从 pending 移除；不要重复实现这部分。

只做规则取证和正式回归测试，不调平衡、不改扑克规则。若测试暴露实际缺陷，先保留复现步骤和失败证据，不自行改变玩法。

## 执行步骤

1. 阅读 `Godot/three_d/rules/table.gd` 中行动队列、短额全押、精确跟注全押及加注权实现，并对照 `Godot/three_d/tests/short_stack_queue_test.gd` 与 `docs/3d-production/phase-1/coverage/transitions.json` 已登记的 `queue.*` 结果。
2. 对剩余两类分别构造最小合法牌局。逐个轮换行动顺序、按钮/盲注相对位置或唯一仍有筹码的玩家位置；记录哪些输入只是同一个语义结果，哪些确实改变可观察后继状态。
3. 新建独立测试文件 `Godot/three_d/tests/poker_queue_remaining_seats_coverage_test.gd`。每个正式结果需断言完整相关后继状态，至少包含行动顺序、欠注/匹配、行动权、当前下注目标及最终牌局状态；不得只断言函数返回值或内部 trace。
4. 只有独立语义后继结果才新增稳定 ID 到 `transitions.json`；被现有 ID 覆盖的输入作为同一 ID 的多个测试案例，不重复扩大分母。只移除已充分审查的 pending family 项，未覆盖项继续保留。
5. 将新脚本纳入 `Godot/three_d/tests/collect_coverage.py`；生成与既有报告同格式的覆盖证据 JSON，并在 `docs/3d-production/phase-1/coverage/README.md` 记录新增结果数、检查数、边界及尚未覆盖项。
6. 运行该专项 Godot 测试、`python3 Godot/three_d/tests/collect_coverage.py`、`python3 Godot/three_d/tests/test_collect_coverage.py`，并做 `git diff --check`。报告命令、Godot 版本、结果文件路径和任何失败。
