## 任务 A4-Catalog：登记已有世界交互后继证据

### 目标

把 A4 世界审计中已有可重复测试、且直接断言了后继状态的结果，与 Phase 1 状态转移目录对齐。只补目录和测试证据映射，不改游戏行为。

### 操作步骤

1. 阅读 `docs/3d-production/external-handoff/A4-world-audit/README.md`、`outcomes.csv` 和当前 `transitions.json`。
2. 仅处理 `outcomes.csv` 中标为“有测试但未登记”的结果。逐项检查当前分支里的真实测试和断言，不以旧日志或注释代替测试。
3. 对语义确实不同、且现有测试断言了后继状态的结果，添加稳定且唯一的 `world.*` ID，并让对应测试写入该 ID 的命中证据。若与已有 ID 表达同一后继，保留原 ID，不重复扩充分母。
4. 不把 `未找到测试`、`unverified`、程序化隔离实验或只断言返回值的结果登记为已覆盖。不要修改生产逻辑、规则、存档或 UI。
5. 更新 A4 README 的现状补记，列出新增 ID、去重决定和仍待处理的结果。

### 成品与验收

- 修改后的 `transitions.json`、对应测试文件及 A4 README 补记。
- 当前受影响的 Godot 测试通过；`collect_coverage.py` 重新生成证据，新增 ID 均有当前哈希和后继状态断言。
- A4 `verify_outcomes.py` 通过；测试命中与目录双向一致，没有重复 ID、未登记命中或把程序化前置冒充玩家可达路径。
- 报告新增结果数、原有 ID 复用数、保留未验证项及完整命令。不要宣称全局覆盖率或 Phase 1 通过。

## 任务 A5-Catalog：登记存档捕获与 RNG 重放已有证据

### 目标

只处理 A5 `outcomes.csv` 中 `capture` 与 `rng_replay` 两组的“有测试但未登记”结果，把现有可靠测试接入状态转移目录。不得更改存档格式或游戏规则。

### 操作步骤

1. 阅读 `docs/3d-production/external-handoff/A5-persistence-audit/README.md`、`outcomes.csv` 和当前 `transitions.json`。
2. 逐项定位 A5 表中 `capture`、`rng_replay` 且已有真实测试后继断言的行；核实测试确实比较恢复后的具体世界/牌桌状态、RNG 值或可见后续结果。
3. 为目录未表达的独立语义增加唯一的 `persistence_*` ID，并在对应测试中发出命中。仅比对 `seed`、只核 `restore()` 返回值或只记录 trace 的情形不算重放/捕获后继证据。
4. 同一后继由多个测试覆盖时复用一个语义 ID，不重复计数；不得顺手补录 A5 其他组或改动生产代码。
5. 同步 A5 README 与 CSV 的目录映射、行数及当前基线说明。

### 成品与验收

- 修改后的 `transitions.json`、对应测试文件、A5 README 和 `outcomes.csv`。
- 所有受影响 Godot 测试与 `collect_coverage.py` 通过；A5 `verify_outcomes.py` 通过，既有 catalog ID 映射无遗漏或重复。
- 附报告列出每个新增 ID 对应的 CSV 行、测试断言、当前证据路径、实际新增数量和仍未覆盖内容。不得把审计范围写成完整存档覆盖。
