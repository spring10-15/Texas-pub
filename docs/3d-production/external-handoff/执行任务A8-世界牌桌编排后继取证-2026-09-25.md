## 执行步骤

1. 阅读 `current-tree-player-path-gaps.csv` 中剩余 12 行、`current-tree-reconciliation.md` 和上述目录 ID 的测试。只处理表内世界层牌桌编排候选，不重做 A4/A5/播放器输入/窗口通知。
2. 新建一个聚焦的 Godot 测试套件，使用当前实际可达的 World、座位/桌面状态和公开入口。每个结果都比较调用前后的完整 Run checkpoint、牌桌公开状态、revision、现金/底池/行动者及相关面板；拒绝情况证明权威状态不变。不要只检查函数返回值、trace 或按钮文本。
3. 对牌桌自动推进使用固定 seed 与确定的玩家/对手 actor 状态。分别验证服务面板/暂停时不推进、无人待行动时推进牌面阶段、对手行动时只执行一个合法动作、下一手按钮路径确实开始下一手。若某个候选在公开玩家路径下不可达，要提供最小复现并标成 `unreachable_or_not_transition`，不得用手工改写生产状态伪装玩家路径。
4. 对强制撤离复用既有测试所走的实际路径，核实服务面板关闭、房间变为藏匿点、压力/出口/金库结果与 `world.leave_forced_pressure_exit` 对齐。不可达的服务面板组合要如实排除，不强造分支。
5. 更新测试命中报告、`collect_coverage.py` 的 suite 声明，以及 `reconcile_current_tree.py` 的固定映射/测试证据引用；更新 `current-tree-gap-triage.md`，逐条写明 12 行落入哪个既有 ID 或为何属于 no-op。不要编辑冻结的 A8 原始 CSV。
6. 运行新增套件、所有受影响套件、`collect_coverage.py`、`python3 -m unittest discover -s Godot/three_d/tests -p 'test_*.py'`、A8 当前树对账、A4/A5 自检和 `git diff --check`。完成后报告每条候选的判定、测试后继、复用 ID、不可达项与全部命令结果。
