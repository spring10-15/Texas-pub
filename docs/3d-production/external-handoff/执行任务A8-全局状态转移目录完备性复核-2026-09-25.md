# 执行任务 A8：全局状态转移目录完备性复核

日期：2026-09-25。此任务供用户分派一名外部 Agent，做当前版本的只读源码审计。目标是验证 `transitions.json` 是否覆盖了所有玩家可达的状态变更结果，为主 Agent 确定全局分母提供独立证据。不要改玩法、测试或覆盖目录，也不要自行把目录状态改成完整。

## 基线与边界

1. 开工时从最新 `origin/main` 开始，记录 commit、Godot 版本、工作区状态；如果执行过程中主线更新，按开工 commit 审计，并明确列出受影响文件，不要把旧审计冒充当前证据。
2. 阅读 `docs/3d-production/phase-1/state-machine.md`、`coverage/transitions.json`、`coverage/README.md` 及 Phase 1 门槛文档。
3. 只读检查以下规则及玩家交互源码：`Godot/three_d/rules/{run,table,poker,opponent,advanced_services,routes,search_events,run_variants,run_checkpoint,table_checkpoint,save_store}.gd`，以及 `Godot/three_d/scripts/{world,player,scene_props,interactable}.gd`。若源码新增了同职责模块，也纳入并记录。
4. 目录有 382 个登记 ID、当前 382/382 有证据，但状态仍为 `incomplete_catalog`。不得把“命中全数已登记 ID”当成“分母完整”。不得推导或宣称整体覆盖率、Phase 1 通过或真人体验通过。
5. 不改 `Godot/`、`transitions.json`、自动测试或既有外部 Agent 交付；不新增语义 ID。缺少证据只报告，不自行修复。

## 执行步骤

1. 从每个模块中列出可由玩家输入或游戏调度触发、且可能改变权威 Run/Table/World/存档状态的公开入口。明确排除纯查询、绘制、装配和格式化 helper，并逐项说明排除理由；不要仅用 `func` 搜索结果当作状态转移全集。
2. 对每个纳入入口，阅读完整函数体，把每个语义上不同的接受结果、拒绝结果、阶段/动作条件及互斥分支拆行。相同后继状态可以归并，但要说明归并依据；不可达的防御分支单独标注并给出调用路径证据。
3. 将每行与当前 `transitions.json` 中的 ID、源函数、结果类型、测试和最新证据报告对应。区分“有 ID 且有后继断言”“有 ID 但证据不足”“未登记但玩家可达”“未登记且不可达/非状态转移”。只核对测试日志或返回值、不核对后继状态的，不能算强证据。
4. 针对未映射的可达结果，给最小复现入口及应补的后继状态断言；不得自行改代码或目录。核对外部 A3/A4/A5 审计与当前源码，旧行号/旧报告不视为当前证据。
5. 复核状态机文档中的资金、库存/道具、风声、位置、RNG 五类权威状态是否均有对应分支清单；指出测试固定夹具与真实玩家可达路径的区别。
6. 记录所有来源文件 SHA-256、覆盖目录 SHA-256，以及复验命令和退出码。审计只用只读命令，不触发正式存档、媒体生成或 UI 截图。

## 成品

交付到 `docs/3d-production/external-handoff/A8-global-catalog-audit/`：

- `README.md`：基线、审计范围、纳入/排除口径、复验命令、摘要、限制；明确回答“目录是否足以冻结分母”，若否，列出具体缺口，不给主 Agent 代做规划结论。
- `branch-inventory.csv`：至少包含 `module,source_file,entry,function_line,branch_or_guard,source_line,outcome,player_reachable,catalog_id,test,evidence_report,evidence_strength,disposition,notes`。
- `unmapped-reachable.csv`：未登记但看起来玩家可达的结果；若无则保留只有表头的文件，并说明核验方法。
- `unverified-or-unreachable.csv`：证据不足、不可达或非状态转移项及理由；不与“覆盖通过”混写。

## 验收

- 每个纳入的公开状态变更入口都有完整函数分支清单；每个分支都映射到目录 ID 或明确 disposition。
- CSV 行可回到当前源码行，ID/测试/报告路径真实存在；随附脚本或人工复核规则能识别悬空路径、目录外 ID、重复映射和分支遗漏风险。
- 独立核对时没有把 helper 数量、测试数量、自动断言数或 381/381 当作全局分母。
- 明确保留真人新手/老手决策差异、正常局计时等不属于自动状态转移分母的验收项。
- 最终回报包含修改文件（应仅为本交付目录）、源码与目录哈希、映射/未映射数量、复核命令/结果，以及无法证明完整的范围。
