### 1.3 关键结论（直接可用的 4 条）

1. **背包展示是 19 件共同的缺口，且是依赖最少的一项。** 现在「背包展示 = 一行文字」，9 件可用道具和 10 件贵重物在背包里长得一模一样（都是名字）。**事实依据**：`services_hud.gd` 全文件只有 `Label` / `Button`，没有任何 `TextureRect`/`Sprite`；`run.gd:440-442` 的 `bag` 是 `item_name()` 拼出的字符串。**为什么说依赖最少**：HUD 只消费 `service_view()` 的返回值、自身不写规则状态（`services_hud.gd:54` 只 `emit`），改展示层不动 `run.gd`。本项只说「覆盖全、改动面小」，**不声明它是收益最高的一项**——收益排序属产品判断。
2. **10 件贵重物没有独立模型，但它们不是「一样地缺」**（详见 §2.3）：按可复用起点分**三组互斥**——装饰层有同名物件 **2** 件、无同名但有同族基底 **3** 件、两者都没有 **5** 件。**「没有同名文件」不等于「没有可复用内容」**——材质库与三个同族物件（打火机、筹码 ×2）仍可借形制。
3. **`baseRewardPool` 是完整情报中的奖励候选展示清单，不编码本局的条件选择。** `service_view()` 用该清单展示一桌可能获得的奖励；当前四桌清单 ID 与 `settle_table()` 的条件奖励分支一致。比如货运桌会按背包内容与筹码量在象牙筹码、红宝石袖扣、旧银打火机之间选择；本局到账仍应以结算结果为准。
4. **货架有一个隐式耦合点。** `bar_display.gd:27` 用字典按 id 取展示高度 `bottom`，且**只登记了 9 件可用道具**。将来往 `shop_stock()` 里加任何新道具，必须同步补这个字典，否则 `bar_display.gd:27` 取值失败——这是加道具时的必查项（不评价它是不是「最容易」踩的坑）。

## 三、人物逐件拆解（9 位）

权威版本见 **`characters.csv`**（9 行 × 22 列）。源文件全部落在 **`assets/blender/characters/build_characters.py`**（9 人一次循环生成，`CAST` 在第 9 行）。

> **每人一行的「现有源文件」与「可复用部件」**（任务书第 1 条对 9 人物与 19 物品同口径）：
> 现有源文件 = `build_characters.py` 的 CAST 序号 + `<id>.blend` 可编辑源 + `<id>.glb` + `manifest.json`；
> 可复用部件 = **14 骨骼 rig** + **4 段剪辑** `idle/bet/win/fold` + 材质库 + `.blend` 可编辑源。
>
> ⚠️ **B2-R1 修正——「几何相同」不等于「文件联动」**：`build_characters.py:33` 对 `CAST` 逐角色循环，**每轮 `:34` 都 `read_factory_settings(use_empty=True)` 重建场景**，`:117` / `:120` 按角色名分别 `save_as_mainfile` / `export_scene.gltf`；`Godot/three_d/scripts/characters.gd:6-21` 的 `actor()` 也是按角色 id 分别 `load()`。
> 所以**九个角色是九个独立文件、各有独立可编辑 `.blend`，不是九个文件链接同一份网格**。同组几何一致的真正原因是**生成算法相同**，而不是文件共享。
> 由此：**改共用生成逻辑并全量重导会影响同组；但按角色参数/分支、或直接改某个 `.blend`，完全可以单独制作。** 因此 §四 顺序 4 里「整组一起改」只是**建议**（保持风格与性能一致），**不是技术前提**。

### 3.1 几何分组是 4 组，不是 3 组

分组口径 = **每角色全部 primitive 的 `POSITION` 原始字节 `sha256` 是否相同**（二进制解析，非文件名、非顶点数）。实测：

| 组 | 成员 | 共用原因 | 造型开关 |
|---|---|---|---|
| **A** | `ash-smuggler`、`dock-braggart`、`river-shark`、`smiling-knife` | 4 人的**导出几何当前一致**（同一生成循环、算法相同；各有独立 `.blend`） | `hat=True`（`build_characters.py:64-65` 多一顶 `Felt hat brim` + `Hat crown`） |
| **B** | `house-viper`、`ledger-clerk`、`velvet-rook` | 3 人的**导出几何当前一致**（同上） | 三开关全 False |
| **C** | `bartender` | 几何独有 | `standing=True`（`:35` `lift=.35`、`:42` 膝/踝位置上提、`:69` Sleeve 用 shirt 材质） |
| **D** | `calm-widow` | 几何独有 | `female=True`（`:63` `Pinned hair`、`:49` Jacket 收窄到 .18、`:55` Cranium/Jaw 尺寸、`:92` Fitted shirt 投影） |

> **为什么必须用字节而不是顶点数**：`bartender` 的 `manifest.json` 顶点数是 39558，与组 B 三人**完全相同**，但 `POSITION` 字节不同（站姿 lift 改变了全部躯干/下肢坐标）。**顶点数相同 ≠ 几何相同。** `manifest.json` 的 `vertices` 是 Blender 导出前的 `len(body.data.vertices)`，与 GLB 的 `POSITION` 总数（UV 拆分后）是两个量，本表两个数都列在 CSV 里。
>
> **实测 GLB `POSITION` 总数**：组 A 41463、组 B 40617、组 C 40617、组 D 39708。

**基础几何共享不是自动失败，但也不能用它反过来证明「人物已完成」。** 本表只陈述事实：组 A 内 4 人、组 B 内 3 人的轮廓完全一致。

### 3.2 只有 3 个造型开关，配色是材质参数

- **造型开关只有 3 个**：`hat`、`female`、`standing`（`build_characters.py:9,33-36`）。除此之外 9 人**没有**任何逐人造型分支——没有道具、没有纹样、没有配饰、没有疤痕/眼罩一类的个人标识。
- **每人可变的颜色只有 2 个**：`suit`(Wool) 与 `hair`(Hair)，都在 `CAST` 里逐人手写。`Skin` 是**按数组下标派生**的公式 `(.38+idx*.008, .23+idx*.005, .15+idx*.004)`（`:36`），不是逐人设计——9 人皮肤色只是**近似等差的一串色值**。
- 其余材质（`Ivory cotton` 衬衫 `.58,.54,.43`、`Polished leather` 鞋、`Brass`）对 9 人**完全相同**。
- 所以「9 套配色」的准确说法是：**9 组唯一的材质参数，其中 2 个是逐人写的、1 个是公式派生的。⚠️ 配色数量不能当作角色辨识度指标**——同组的 4 人（或 3 人）只靠西装/发色的深浅差来区分。

### 3.3 现有动画：4 段剪辑，每段只驱动 1–2 根骨骼

`build_characters.py:102-113` 生成 `idle` / `bet` / `win` / `fold` 四段（帧数分别为 61 / 25 / 31 / 31）。**逐段关键帧只有这些**（`:108-110`）：

| 剪辑 | 驱动的骨骼 | 幅度 |
|---|---|---|
| `idle` | `head` | `.025` rad |
| `bet` | `head` + `forearm.R` | `.035` / `-.25` rad |
| `win` | `head` + `spine` | `-.09` / `-.04` rad |
| `fold` | `head` | `.12` rad |

**测试实际验证到什么程度**：`Godot/three_d/tests/characters_test.gd:23` 只断言每段「≥ 1 条轨道」，`:29` 只断言 `fold` 播放后 **`head` 的旋转变化 > 0.02 rad`**。也就是说，**当前测试保证的是「骨骼会动」，不保证任何动作表现质量**——「发牌 / 下注 / 递物」目前都只是上述 1–2 根骨骼的摆动。

运行链路：`characters.gd:6-21 actor()` 实例化 → `:22-27 build()` 固定座位（`x = −1.1 / 0.25`，酒保 `2.55/0/.4` yaw `−π/2`）→ `:32-42 sync()` 换桌重建 → `:44-56 refresh()` 每手按公开动作触发 → `:57-59 deliver()` 递物。

### 3.4 可识别性检查项（不能用配色数替代）

对**每一位**角色，B2 都写进了同一条硬检查，逐人实机确认：

> 在**实际座位距离**（`characters.gd:26` 对手席 `x = −1.1 / 0.25`）与**牌桌照明**（`world.gd:285-286` 主光 2.2 / 1.0 + `tavern_layout.gd:80-81` 1.1 / 1.4 + `world.gd:311-318` FILMIC 色调映射 + ambient color）下，能否分辨该角色与同组其他人。
>
> - 组 A（4 人）/ 组 B（3 人）的成员：**同组轮廓完全一致，只能靠西装/发色深浅区分**——本表里区分度最低的一档。
> - 组 C / 组 D：靠几何区分（站姿 / 束发 + 女装投影），区分度高于同组成员。
> - ⚠️ **不可用「9 套配色」当作 9 人独立完成的证据。**

> **本检查项是「需实机确认」，不是「已验证通过」。** B2 只提供检查方法与被检查事实；判定需要真人试玩或截图比对，本轮未做（`--capture` 路径存在但生成图片属「生图」，本轮按边界未执行）。
>
> 另外：**9 位人物没有任何逐人参考图**（见 §1.4）——只有 2 张整体场景板作依据，且 `assets/blender/characters/README.md:9` 作者自述「这不是最终人物美术…体素面部仍需适合表情的拓扑、UV/磨损贴图、个性化五官、指骨与自然发牌/下注/递物动画」。该列在 `characters.csv` 的「参考图」列逐人标注。
