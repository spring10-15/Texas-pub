# 子 Agent 执行任务 A3：扑克状态转移分母取证

交给一名外部子 Agent 独立执行。目标是把当前覆盖目录尚待拆分的扑克边界逐条核对为可复现的事实清单，供主 Agent 决定是否增补目录和回归。**本任务只取证，不改规则、不改覆盖目录、不宣布 Phase 1 通过。**

## 工作范围

- 只读核对 `Godot/three_d/rules/table.gd`、`poker.gd`、`table_checkpoint.gd`，以及 `Godot/three_d/tests/` 中对应测试。
- 对照 `docs/3d-production/phase-1/coverage/transitions.json` 的现有 `poker_*`、`queue.*`、`ending.*`、`payout.*` 结果，检查以下六项待拆分边界：`short_all_in`、`exact_call_all_in`、`queue_reopen`、`lone_funded_queue`、`aggression_discount`、`next_hand_heads_up`。
- 只写 `docs/3d-production/external-handoff/A3-poker-audit/` 下的新交付文件；如需诊断日志，仅写 `output/external-handoff/A3/`。不得修改生产代码、既有测试、覆盖目录、玩家存档或其他 Agent 的交付；不要提交、推送。

## 逐步执行

1. 记录 `git rev-parse HEAD`、`git status --short`、Godot 版本。若工作区已有改动，保留原样；所有结论标明基于哪个 HEAD 和源文件。
2. 从 `table.gd` 的公开入口 `legal_actions`、`act`、`advance`、`next_hand`、`start_hand` 出发，逐项追踪六类边界。每个可到达的**不同语义结果**列一行；不同种子或数值但后继状态等价的样本不重复计数。拒绝结果要检查是否保持完整牌桌状态不变，成功结果要写出筹码、底池、行动队列、街道、庄位及 RNG 中实际受影响的字段。
3. 为每行找现有测试及覆盖 ID。分别标记：`已登记且有后继状态证据`、`有测试但未登记`、`未找到测试`、`不可到达`。若判断不可到达，写清被哪条前置守卫排除；不要因为源码有一个 `if` 就把它算成可达结果。
4. 对“未找到测试”或“现有测试与源码矛盾”的行，在本任务目录 `repro/` 写最小只读诊断脚本（若确需运行）；使用 Godot 的 `--headless --path Godot --script ... -- --test` 执行，日志保存到 `output/external-handoff/A3/`。脚本只在内存中构造牌局，不读写正式存档。若无需脚本，记录具体代码行和现有测试断言即可。
5. 复核所有行的证据路径存在、代码行号属于所记 HEAD；日志必须检查 `SCRIPT ERROR` / `ERROR`，不能只凭退出码判断通过。发现疑似规则缺陷时只给最短复现与实际结果，不自行改规则。

## 必交成品

在 `A3-poker-audit/` 交付：

- `README.md`：基线、使用的命令、六项各自的结论、已知验证边界、疑似缺陷列表（没有就写“未发现”）。
- `outcomes.csv`：至少包含 `family,source_entry,source_line,precondition,action,accepted_or_rejected,postcondition,existing_catalog_id,existing_test,evidence_status,evidence_path,notes`。六个 family 都必须出现；同一结果若被多个测试命中，只保留一行并在 `existing_test` 列并列列出。
- `repro/` 与 `output/external-handoff/A3/`：仅在第 4 步确需新增诊断时交付脚本和原始日志；否则 README 明确写“无需新增诊断脚本”。

## 主 Agent 验收方式

逐行抽核六类边界、源代码、现有 ID 与测试；确认 CSV 可解析、无虚构命中、拒绝后状态未变的说法有证据。此任务的成品是**覆盖分母取证清单**，不是新增覆盖率，也不代替主 Agent 修改目录、编写正式回归或作玩法取舍。
