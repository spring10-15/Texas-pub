## 一之二、资金守恒的闭合边界（C1 新增，门槛 1 的口径前提）

初版把门槛 1 的通过条件写成 **`金库变化 + 随身变化 + 损失 = 0`**，这是一个**无条件等式**，是错的：它只在**特定的阶段边界**上成立，且**漏了五类载体**。返修后按下表执行。

**玩家侧财富共有六个载体**，任一时刻的闭合式必须把它们全部写进去：

| 载体 | 字段 / 来源 | 何时在等式里 |
|---|---|---|
| 金库 | `run.vault` | 全程 |
| 随身现金 | `run.cash` | 全程 |
| **桌上筹码** | `table.state.players[0].stack`（买入后、离桌前） | **手牌进行中必须计入**，不能只算 `cash` |
| **未分配底池** | `table.state.pot` | **手牌进行中必须计入**（`finish_hand()` 之后、下一次 `start_hand()` 之前，pot 尚未清零——这是最容易被漏算的坑） |
| 物品价值 | `run.valuable_total()`（`run.gd:451`） | 持有贵重物时 |
| 抵押托管 | `run.collateral` | 抵押期间（是**转移**，不是销毁） |

**还有两类"非玩家侧"的转移与两类显式收支，不能并入玩家侧等式去要求为 0：**

- **对手转移**：对手赢/输的筹码在对手之间流动。玩家侧等式只约束"玩家自己的进出"，**不能用全桌总额等于常数来代替**（除非把两名对手的 stack 也写进同一条等式）。
- **奖励**：`run.gd:199-204` 的奖励物品是**显式来源**（背包新增），会增加玩家侧财富；必须作为来源项写出，不能算成"无来源增值"。
- **费用**：手续费（`routes.gd:11` 的 `平费 + floor(现金 × 费率) + 封锁附加`）、转场车费 15 + 出口费、降风声费、预约预付 —— 都是**汇**（sink）。
- **舍弃**：`dropbag-*` 的舍弃现金（`lostCash`）与舍弃贵重物（`lostGoods`）也是汇。

**权威表述以 `docs/3d-production/phase-1/state-machine.md` §守恒等式 为准**（本轮已复核与代码一致），逐阶段闭合式为：

| 阶段 | 闭合式 |
|---|---|
| 出发 | `金库减少 = 带出本金 = 随身现金增加`，且 `带出本金 = min(300, 金库)` |
| 入桌 | `随身现金减少 = 玩家初始筹码`；抵押是背包→托管，不是销毁 |
| 单手（进行中） | `Σ 所有玩家剩余筹码 + 未分配底池 = 本手开始总筹码`（对手也计入） |
| 离桌 | `随身现金增加 = 玩家剩余筹码`；奖励作为显式来源 |
| 成功撤离 | `原现金 + 原贵重物价值 = 到账 + 手续费 + 舍弃现金 + 舍弃贵重物价值`，且 `金库增加 = 到账`、随身与背包清空 |
| 失败（放弃） | `金库增加 = min(80, 现金)`（仅持夹层钱包时），其余登记为损失 |
| 转场（牌桌之间） | `金库不变`；`随身减少 = 出口费 + 15 车费`；行动力 −1 |

**存在性证据**：`venue_transfer_test.gd:69 / :75` 用的正是 `night.vault + night.cash + night.valuable_total() == expected_total` —— **这条件成立的前提是"此时不在手牌中、也没有抵押"**，即它只在牌桌之间的检查点可用。把它当成任意时刻的守恒式会误判。

> **纪律**：以后写"资金守恒通过"时，必须同时给出 **① 阶段边界、② 等式全文（含全部六个载体与来源/汇项）、③ 该检查点是否在牌桌/抵押中**。缺任一项不得宣布通过。
