# 首次游玩记录模板

用途：给**真人**填。每一位测试者一份，文件名 `first-play-<测试者编号>-<日期>.md`。

**填写纪律（必须遵守）**

- 只填真实发生的。**没打开的项写"未执行"，不要补默认值。**
- 不虚构测试者和时长。空的就空着，写"未执行及原因"。
- 这份记录**不能**代替自动规则测试，也**不能**代替性能测试；三者分开。
- 时间一律用实际钟表时间（`HH:MM:SS`），不要用视频时长倒推。

## 3. 资金结算核对

| 项 | 测试者看到的数字 | 记录者实算的数字 | 是否一致 |
|---|---|---|---|
| 带出本金 | | `min(300, 金库)`；**对照模式**新启动金库 1200 → 应为 **300** | |
| 第一桌买入 | | 该桌 `buyIn`（货运桌 60；账房 90；镜厅 120；余烬桌 160） | |
| 离桌返还筹码 | | 应等于剩余筹码 | |
| 撤离手续费 | | 通式：`当前酒馆平费 + floor(现金 × 该店费率) + (风声恰为 5 ? 封锁附加 : 0)`（`routes.gd:11`；`floor` 是向下取整） | |
| 最终到账 | | `max(0, 现金 − 手续费 − 舍弃现金) + 贵重物价值`（`routes.gd:51`） | |
| **本局金库落点** | | **= 出发前金库 − 带出本金 + 最终到账**。对照模式：`1200 − 300 + 到账` | |

**四家酒馆的撤离参数**（`content.json`，2026-09-22 基线）

| 酒馆 | 平费 | 费率 | 风声恰为 5 时的封锁附加 |
|---|---:|---:|---:|
| 烟雾酒馆 smoky-den | 24 | 0.12 | 45 |
| 高层酒馆 high-rise-suite | 42 | 0.18 | 70 |
| 屋顶酒馆 rooftop-club | 28 | 0.13 | 60 |
| 霓虹酒馆 neon-poker-club | 34 | 0.14 | 55 |

> `24 + 现金×12% + 45` **只适用烟雾酒馆**，而且**省掉了向下取整**——只在烟雾酒馆、且不跨店时才能用；跨酒馆必须按上表换参数。
> 风声 ≥ 6 时普通出口直接封锁、**不出报价**，封锁附加只在风声**恰好等于 5** 时加。
> `金库落点` 那一行是必须核的：出发时金库**已经扣过本金**，撤离时只加"到账"。把金库写成 `出发前金库 + 到账` 就会凭空多出一份本金。

> 带出本金**没有手动选择的余地**（`run.gd:61` 自动取小），所以它**不是**一个决策点，不要记进 `decision-record-template.csv`。

有任何一行"不一致"→ **立刻停手并保留截图**，这是 gate 1（账目零误差）的直接反例。
