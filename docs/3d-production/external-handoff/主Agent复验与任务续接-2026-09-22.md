## 验收结论

**B1 接收为现状与制作参考，不能据此宣布 Phase 2/3 完成。** 内容表 56 行已拆分实现与验证状态；酒保 GLB 已接入、道具为一个 GLB 内命名部件等主要误判已更正。本次独立解析九个角色 GLB 的 POSITION 字节并分组，确为四组：四个男角色共享一组；house-viper/ledger-clerk/velvet-rook 一组；bartender 与 calm-widow 各一组。它证明导出几何分组，不证明人物美术辨识度达标。贵重物缺独立交互模型的结论可用于后续制作，不能把“没有同名文件”单独当作完整资产内容审计。

**C1 模板结构接收，真人协议还需 C2 返修。** 正常局起止时间已修正，示例与实测已分开。以下仍不能用于验收：

1. 用户目标是“决策次数差异 >3”，不能改成分歧率或选择不同的次数。采用实际决策事件数的绝对差 `abs(N_experienced - N_new) > 3`，同时保留原始 N、机会数和选择内容供解释；选项分歧只作辅指标，不能替代主门槛。差异达标也不自动证明体验成立，仍需玩家理由与复盘。
2. 计数单位：玩家在至少两个合法玩法选项中做出并成功执行的一次选择。拒绝动作、重复点击、镜头操作、纯移动、翻页不计；自动发牌和 AI 动作不计。一次决策即一条事件，不能说实际动作数必然不小于机会数。
3. 出发本金当前自动取 min(300, 金库)，没有手动选择本金的功能，不能把“是否照搬默认本金”列成决策点。改记录实际可选的酒馆、下注、道具、抵押、搜索及撤离选择。
4. 相同种子与路径只能控制起始布局、桌序等条件；不同行动会改变后续局面，不能把两人的第 N 行强行当成同一个局面。记录分叉时点，区分同路径对照和逐局面配对。
5. 当前普通启动随机出发，协议未提供可执行的固定种子启动入口。不要让测试者改生产代码，也不要重置真实存档来凑相同初始金库。主 Agent 下一步提供隔离的固定种子试玩入口后再正式收数。
