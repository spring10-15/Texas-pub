## B2 必修项（改原目录三份文件，不另建资产库）

### B2-R1：几何相同不等于文件联动，也不要求整组同时改

README §三/§四与 characters.csv 写了“改一处即改全组”“单独改 1 人无法拉开组内区分”。这不成立。

证据：`assets/blender/characters/build_characters.py` 每轮 `read_factory_settings` 后创建角色，按角色名分别保存 `.blend` 和 `.glb`；`Godot/three_d/scripts/characters.gd::actor` 按角色 ID 分别加载。当前生成算法相同产生相同几何，不是九个文件链接同一个可编辑网格。

修改：区分“修改共用生成逻辑并全量重导会影响同组”与“按角色参数/分支或独立源文件可以单独制作”。可以建议整组检查风格与性能，不得写成必须同时制作的技术前提。不要为证明此事实际改模型或重导。

### B2-R2：参考图去重与用途分类过强

README §1.4 从两张同字节文件推出“现有 3D 参考图去重后只有 1 张”。独立 SHA-256 检查显示：酒保交易视角与酒馆全貌确实相同；但牌桌视角、藏匿点、厨房撤离、撤离视角各有不同哈希。这六个文件去重后是五份图片，不能推出所有参考只剩一份。

修改：仅报告已核对集合与重复组。“2D 背景”也不能自动判为不可作建模参考；未逐图审阅的写“内容适用性未核验”。没有逐人设计图不等于必须先生成图片，是否需要补图仍由主 Agent 判断并向用户确认。

### B2-R3：贵重物入包及数量分组

README §1.2 的“只有 SUPPORTED_ITEMS 九件能进背包”应为“购买入口仅支持这九件”。`run.gd::settle_table` 明确将贵重物加入 inventory。§2.3 的分组写成 2+2+8，同时又说“除上面四件外”，数字不自洽。

修改：用互斥分组，例如同名装饰 2、无同名但同族基底 2、其余 6；古币若另列部分复用，明确分组归属。移除仅由“无同名物”推导“必须从零建”的结论，写清具体可复用几何与未核实部分。

### B2-R4：基础货架候选与种子实架分开

README 上架位统计来自 content.shops，是基础候选。`run_variants.gd::generate` 在正种子下会从非必需候选中移除一件；`run.gd::shop_stock` 优先使用生成计划。不能把候选位数写成当前每次必定实物上架的位数。

修改：表头与 CSV 注明“基础配置候选位”；保留手机第二档补货说明，但补上种子计划的优先路径。无需扩大统计样本或新增展示功能。

成品：修订 `B2-production-breakdown/README.md`、`items.csv`、`characters.csv`，在 README 加简短返修记录。验收：仍为 19/9 个唯一 ID；全文不再包含上述错误制作前提；事实、建议、未核实分开。

## C2 必修项（改原 C 目录文件）

### C2-R1：分叉从首次状态不同开始

`decision-metric-example.md` 两人第 1 次行动已分别跟注/加注，却把第 7 条标为分叉，后续翻牌还当相同局面比较。这与协议 §2.1 自相矛盾。

修改：首次行动就标分叉；没有完整前置状态相同的证据，后面的记录不得配对。或者重写一组分叉前行动完全一致的虚构示例。重新计算辅指标，不以相同序号证明同局面。

### C2-R2：同路径示例不能有不同酒馆行程

例子声明双方“烟雾酒馆 / 只打货运桌 / 普通出口”，老手第 10 条却转入高层酒馆。这组可作自由玩法示例，不能作同路径主门槛判断。

修改：两人遵守同一酒馆序列、桌序及撤离方式，或将原例明确标为“不合格对照、不可判断门槛”，再给一组合格示例。不能保留“同路径且该差值未达标”的结论。

### C2-R3：不行动与成功执行的拒绝选择分开

例子把“不买”“不抵押”记为成功执行，又把“放弃”一概排除，缺少可核对的行为依据。关闭服务面板或没点购买本身不是游戏成功执行的交易；另一方面，成功确认放弃本局会改变资金，不能因为文字含“放弃”就排除。

修改：事件必须有实际动作、合法选项与成功执行依据；未选择/离开面板写观察记录，不计 N。明确区分未作选择与执行拒绝/放弃命令。示例中的“领取外套”也应对照真实搜索选项，当前事件是拿银打火机或抄线索。重新逐行计数，不保留旧 N 凑目标值。

### C2-R4：机会数、计时与手续费可复算

协议要求保留机会数，但 CSV 缺机会 ID/机会是否计入/关联尝试，首次记录模板也没有机会总数。重试时容易一条动作算成多个机会。

修改：补最少必要字段，给一次被拒绝后成功重试的例子，机会只计一次、成功事件一次。模板将“撤离确认时刻”改为“撤离完成时刻”；普遍使用的手续费核对公式写为当前酒馆 flat + floor(cash × rate) + 风声 5 附加费，或明确锁定烟雾酒馆普通出口。现有 24+12%+45 只适用于烟雾酒馆，且漏写向下取整；四店参数见 content.json，算法见 `routes.gd::quote`。

成品：同步修订协议、CSV、首次记录模板、虚构统计示例和 `C2-corrections.md`。验收：一组有效同路径例、一组明确无效的路径偏离例；N、机会数、分叉、计时逐项可重算；虚构记录不混入正式数据。不要新增真人结果，不改游戏代码，不接触正式存档。
